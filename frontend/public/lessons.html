Lessons Learned

Insights and reflections from building the Centralized Student Dashboard

Key Takeaways

What we learned through challenges, pivots, and successes

1. Data Integration is Time-Intensive

Initial timelines were too optimistic. Robust pre-processing and ensuring referential integrity are high-risk early phase activities.

The Challenge: Creating a synthetic dataset with 1,000 students across 6 entities required careful planning to maintain logical coherence. Ensuring that Student_ID correctly linked all records, that enrollment histories made sense chronologically, and that risk factors exhibited realistic correlations took significantly longer than anticipated.

The Lesson: Allocate 30-40% of project time to data preparation, validation, and testing. Data quality issues compound downstream, affecting everything from algorithm accuracy to UI rendering.

2. Prioritizing Value Over Features

The team had to strictly scope the prototype to the highest-value features (risk identification and profile viewing), deferring complex automation to the next phase.

The Challenge: Initial ambitions included automated email alerts, machine learning model retraining, and integration with external student information systems. These features, while valuable, would have prevented timely delivery of the core functionality.

The Lesson: Demonstrate value with a Minimum Viable Product (MVP) focused on solving the core problem: timely intervention. Advanced features can be added iteratively once the foundation proves valuable to stakeholders.

3. Technology Choice Matters

The decision to pivot to the React/FastAPI/MongoDB stack, while introducing a learning curve, ultimately provided a more scalable, flexible, and portfolio-ready product compared to the initial Django/PostgreSQL plan.

The Challenge: Mid-project technology changes created temporary slowdowns as team members learned new frameworks. Documentation was sparse for specific use cases, requiring trial-and-error debugging.

The Lesson: Choose technologies that align with both project requirements AND team learning goals. The modern stack made the prototype more impressive for portfolio purposes and better prepared the team for industry roles. The short-term pain yielded long-term gain.

Project Timeline

Key phases and milestones

Phase 1

Problem Definition & Research

Identified HSU's retention challenge, conducted stakeholder interviews, and performed literature review. Validated multi-factor approach through academic research.

Phase 2

Data Design & Synthesis

Created synthetic dataset with 1,000 students across 6 entities. Normalized to 3NF and embedded realistic correlations for algorithm testing.

Phase 3

Technology Pivot

Switched from Django/PostgreSQL to React/FastAPI/MongoDB for better scalability and modern architecture. Steeper learning curve but stronger outcome.

Phase 4

Algorithm Development

Implemented 40/30/20/10 weighted risk assessment model. Validated against synthetic data showing 75% of critical-risk students had combined academic/financial issues.

Phase 5

UI/UX Implementation

Built Dashboard View, Pulse Tracker, and Student 360° Profile with React. Integrated Chart.js for data visualization.

Phase 6

Testing & Refinement

User testing with mock advisors, performance optimization, and ethical considerations documentation. Achieved 40% faster data retrieval vs. manual queries.

Team Reflection

Building the Centralized Student Dashboard taught us that meaningful innovation requires balancing ambition with pragmatism. While we started with grand visions of machine learning and full system integration, our most valuable contribution was creating a functional, usable prototype that demonstrated clear value to advisors.

The project reinforced that technology serves people. Our risk assessment algorithm is only as good as the trained advisors who use it ethically and contextually. The dashboard doesn't replace human judgment—it enhances it by providing timely, comprehensive information.

If we were to continue this project, priorities would include:

  • Pilot testing with real advisors to gather usability feedback
  • Integration with live student information systems
  • Longitudinal outcome tracking to validate intervention effectiveness
  • Machine learning model refinement based on real retention data
  • Mobile-responsive design for advisors in the field

From Concept to Reality

What started as a response to HSU's retention challenge became a comprehensive demonstration of how data integration, predictive analytics, and thoughtful design can transform student advising from reactive to proactive.
