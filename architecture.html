System Architecture

Three-tier architecture for scalability and performance

Scalable 3-Tier Architecture

The Centralized Student Dashboard implements a modern three-tier architecture designed for scalability, maintainability, and performance. Each layer has a clear separation of concerns, enabling independent development and optimization.

Architecture Layers

01

Presentation Layer

The React SPA handles the user interface, state management, and visualization.

  • Framework: React 19.0
  • State Management: React Context API
  • Visualization: Chart.js
  • Responsive: Device-agnostic experience
  • Features: Dashboard View, Pulse Tracker, Student 360° Profile
02

Application Layer

The FastAPI server hosts business logic, risk assessment algorithm, and API endpoints.

  • Framework: FastAPI (Python)
  • Async: Non-blocking I/O for concurrent requests
  • Risk Algorithm: Multi-factor weighted scoring (40/30/20/10)
  • API Endpoints: RESTful design
  • Data Aggregation: Complex queries for unified profiles
03

Data Layer

MongoDB serves as the flexible document store for all student data.

  • Database: MongoDB (NoSQL)
  • Collections: Students, Financials, Housing, Enrollments, Courses, Advisors/Alerts
  • Key Design: Student_ID as primary linking key
  • Normalization: Third Normal Form (3NF)
  • Performance: Aggregation pipelines for efficient queries

Technical Design Decisions

Why we chose this technology stack

React + FastAPI + MongoDB

The pivot from the initial Django/PostgreSQL plan to the React/FastAPI/MongoDB stack provided superior performance and schema flexibility. MongoDB's document model allows for new metrics to be added rapidly without schema migrations, while FastAPI provides the async speed needed for real-time analytics for a large student body.

Async/Await Pattern

FastAPI's async capabilities ensure non-blocking I/O operations, critical for handling concurrent requests from multiple advisors accessing the dashboard simultaneously. This architectural choice supports scalability from 1,000 to 10,000+ students without performance degradation.

Document-Based Storage

MongoDB's flexible schema accommodates the heterogeneous nature of student data (academic, financial, housing, engagement) without forcing rigid relational constraints. Aggregation pipelines enable efficient reconstruction of Student 360° Profiles with a single query.

Data Flow

1. User Request: Advisor accesses Student 360° Profile through React interface

2. API Call: Frontend sends authenticated request to FastAPI endpoint

3. Data Aggregation: Backend queries MongoDB, aggregating data from multiple collections using Student_ID

4. Risk Calculation: Algorithm computes multi-factor risk score (40% GPA + 30% Attendance + 20% Engagement + 10% Financial)

5. Response: FastAPI returns unified student profile with risk assessment

6. Visualization: React renders data with Chart.js visualizations and interactive components
